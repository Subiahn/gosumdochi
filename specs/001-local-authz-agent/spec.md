# 기능 명세: 로컬 접근 권한 에이전트

상태: Draft · SDD v0.1 기준

## 사용자 시나리오

개발자는 실습 앱 URL과 계정 A/B를 설정하고 run을 실행한다. 에이전트는 공개 페이지와 API 응답을 관찰하고 접근 권한 가설을 세운다. 각 계정의 정상 동작과 교차 접근 결과를 비교해 확인됨·기각·근거 부족을 구분한다. 사용자는 보고서에서 증거 ID와 계정별 요청 결과를 추적할 수 있다.

## 요구사항

| ID | 요구사항 |
| --- | --- |
| FR-01 | plan은 설정을 검증하고 네트워크 요청을 하지 않는다. |
| FR-02 | run은 단일 대상과 계정 A/B를 지원한다. |
| FR-03 | Planner는 스키마에 맞는 가설·행동 후보를 생성한다. |
| FR-04 | Judge는 주어진 후보 ID만 선택하며 임의 도구 인자를 만들지 않는다. |
| FR-05 | 모든 대상 요청은 Policy와 주소 검사를 통과한다. |
| FR-06 | 대상 응답은 관찰 데이터로 취급한다. |
| FR-07 | 서로 다른 계정의 인증 상태를 격리한다. |
| FR-08 | 모델 판단과 결정론적 비교 검증을 별도 기록한다. |
| FR-09 | 모든 finding은 존재하는 verification과 evidence ID를 참조한다. |
| FR-10 | 종료·취소·오류에도 저장된 기록으로 불완전 보고서를 만들 수 있다. |
| FR-11 | 보고서 재생성 시 모델 또는 대상에 접속하지 않는다. |
| FR-12 | 모델·프롬프트·도구 계약 버전을 실행 메타데이터에 기록한다. |

## 수용 시나리오

| ID | Given / When | Then |
| --- | --- | --- |
| AC-01 | 취약 모드·유효한 A/B 계정으로 실행 | 소유권·marker·신원·재조회 증거를 연결한 confirmed가 생성됨 |
| AC-02 | 수정 모드에서 같은 시나리오 실행 | 해당 교차 접근을 confirmed로 보고하지 않음 |
| AC-03 | 로그인 실패 또는 동일 계정 두 개 제공 | 비교 실험을 확정하지 않고 원인을 기록 |
| AC-04 | 외부 URL 또는 호스트 Ollama URL을 모델이 제안 | 대상 도구에서 네트워크 전송 전 거부 |
| AC-05 | 대상이 외부로 리다이렉트 | 리다이렉트를 따라가지 않음 |
| AC-06 | DNS가 허용 CIDR 밖 주소를 반환 | 연결하지 않고 denied 기록 |
| AC-07 | 대상 본문이 정책 변경 지시를 포함 | 범위·도구 권한이 유지됨 |
| AC-08 | Judge가 존재하지 않는 후보 ID 반환 | 실행하지 않으며 제한된 복구 후 불완전 종료 |
| AC-09 | 상태 코드만 같고 소유권 증거가 없음 | inconclusive이며 confirmed 없음 |
| AC-10 | 요청 예산 초과·반복 루프·Ctrl+C | 한도 초과 요청 없음, stop_reason과 보고서 남음 |
| AC-11 | 인증 응답 및 요청 기록 저장 | 알려진 비밀과 세션 값이 모델 입력·결과 파일에서 마스킹됨 |
| AC-12 | 저장된 run으로 report 재생성 | 네트워크 없이 동일 증거 참조를 가진 보고서 생성 |

## 실험 절차

자동 테스트는 fake 모델로 결정론적으로 수행한다. 실제 모델은 취약/수정 모드 각각 5회 실행하고 전체 결과·실패·inconclusive를 공개한다. 초기 통과 목표는 취약 모드 5회 중 4회 이상 확인, 수정 모드 false confirmed 0회다. 이는 목표값이며 아직 측정 결과가 아니다. 성능 기준 미달 시 프롬프트·모델·도구 문제를 분리해 분석한다.
agent에는 앱 모드, 평가 정답, 내부 seed 파일을 전달하지 않는다. 테스트에서만 평가기가 정답에 접근한다.
